# Database

Current state: five tables (`users`, `sessions`, `audit_log`, `farm_settings`, `auth_tokens`). Migrations `0001` to `0005`.

## Accounts and databases

| Name | Purpose | Rights |
|---|---|---|
| `pillbrook_owner` | Runs migrations | Owns the databases; can create, alter and drop tables. Not a superuser. |
| `pillbrook_app` | The running application | Connect; read and write rows in tables the owner creates. Cannot create, alter, truncate or drop. Not a superuser. |
| `postgres` | One-time setup only | Superuser. Its password never goes in the project. The app refuses to use it. |

| Database | Use |
|---|---|
| `pillbrook` | Development data |
| `pillbrook_test` | Automated tests only. Tests undo migrations here, so names must end in `_test`. |

## Migrations

| Revision | What it does |
|---|---|
| `0001` | Removes the right to create objects in the `public` schema from everyone, lets the app account use the schema, and grants the app account SELECT, INSERT, UPDATE, DELETE on all tables the owner creates later. Downgrade reverses this. |
| `0002` | Creates `users`: UUID key generated by the database, name, unique lowercase email, password hash, role (admin, manager or user), email verification time, active flag, creation time. Check constraints enforce the allowed roles and lowercase emails. |
| `0003` | Creates `sessions` (fingerprint of the session code, last activity, absolute expiry; removed with its user) and `audit_log` (time, event type, who, target, detail, address). Removes UPDATE and DELETE on `audit_log` from the application account so entries can only be added and read. |
| `0004` | Creates `farm_settings` (the encrypted farm access code) and `auth_tokens` (one-time links: only a fingerprint, the purpose, expiry and use time; removed with their user). A check limits `purpose` to `verify_email` and `reset_password`. |
| `0005` | Adds `must_change_password` (default false) and `temporary_password_expires_at` to `users`, with a check that an expiry exists only while a change is required. |

## Tables

### `users` (0002, extended by 0005)

| Column | Type | Notes |
|---|---|---|
| `user_id` | UUID | Primary key, generated by the database |
| `name` | text, up to 100 | |
| `email` | text, up to 254 | Unique. A check requires it to be lowercase |
| `password_hash` | text, up to 255 | Argon2id hash. The password itself is never stored |
| `role` | text, up to 20 | A check allows only `admin`, `manager` or `user` |
| `email_verified_at` | timestamp with time zone | Empty until the address is confirmed (or when verification is switched off) |
| `is_active` | true or false | Default true |
| `created_at` | timestamp with time zone | Default: now |
| `must_change_password` | true or false | Default false. True while a temporary password has not yet been replaced |
| `temporary_password_expires_at` | timestamp with time zone | Empty unless a temporary password is pending. A check allows a value only while `must_change_password` is true |

### `sessions` (0003)

| Column | Type | Notes |
|---|---|---|
| `session_id` | UUID | Primary key |
| `user_id` | UUID | The person who signed in. Removed with the person |
| `token_hash` | text, 64 | Unique. SHA-256 fingerprint of the session code in the cookie; the code itself is never stored |
| `created_at` | timestamp with time zone | |
| `last_seen_at` | timestamp with time zone | Idle expiry: 60 minutes |
| `expires_at` | timestamp with time zone | Absolute expiry: 12 hours after sign-in |

### `audit_log` (0003)

| Column | Type | Notes |
|---|---|---|
| `log_id` | UUID | Primary key |
| `created_at` | timestamp with time zone | |
| `event_type` | text, up to 50 | For example `login_success`, `access_denied`, `registration_success`, `password_changed` |
| `actor_id` | UUID | Who did it. Emptied (not deleted) if the person is removed |
| `target` | text, up to 254 | Usually an email address or a permission name |
| `detail` | text, up to 255 | A short reason. Never a password, code or one-time link |
| `ip_address` | text, up to 45 | Empty until the hosting proxy is understood (Step 6) |

The application account can add and read rows but never change or delete them.

### `farm_settings` (0004)

| Column | Type | Notes |
|---|---|---|
| `setting_key` | text, up to 50 | Primary key. Today only `farm_access_code` |
| `value_encrypted` | text | Fernet-encrypted. A copy of the database does not reveal the code. If `SECRET_KEY` changes, it can no longer be read and the Administrator sets a new code |
| `updated_by` | UUID | The person who set it, or empty if set by the command or the person was removed |
| `updated_at` | timestamp with time zone | |

### `auth_tokens` (0004)

| Column | Type | Notes |
|---|---|---|
| `token_id` | UUID | Primary key |
| `user_id` | UUID | Removed with the person |
| `purpose` | text, up to 30 | A check allows only `verify_email` and `reset_password` |
| `token_hash` | text, 64 | Unique. SHA-256 fingerprint of the code in the emailed link; the code itself is never stored |
| `created_at` | timestamp with time zone | |
| `expires_at` | timestamp with time zone | 24 hours for confirmation links, 1 hour for reset links |
| `used_at` | timestamp with time zone | Empty until the link is used; a used link cannot be used again |

## What the application account may do

| Table | Read | Add | Change | Delete |
|---|---|---|---|---|
| `users`, `sessions`, `farm_settings`, `auth_tokens` | Yes | Yes | Yes | Yes |
| `audit_log` | Yes | Yes | **No** | **No** |

It can never create, alter, truncate or drop a table.

## Rules

- Change the database only through Alembic migrations. Never edit a migration that has been applied.
- Primary keys are UUIDs. Timestamps are timezone-aware.
- Allowed values (role, purpose, and later priority and status) are enforced with check constraints.
- Constraint names follow the convention in `app/database.py`.
- Every migration is tested up and down on `pillbrook_test`.
- No password, session code, access code or one-time link is stored in readable form anywhere in the database.
